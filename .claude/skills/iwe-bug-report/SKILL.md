# Отчёт об ошибке платформы IWE

Проблема: $ARGUMENTS

## When to use

Сообщить об ошибке или проблеме платформы IWE. **Гейт (решение пилота 2026-09-17):
по умолчанию скилл готовит отчёт локально и НЕ отправляет его вендору** — см. Шаг 4.
Отправка issue в `TserenTserenov/FMT-exocortex-template` возможна только по явному
одобрению пилота в текущем диалоге.

## Algorithm

## Шаг 0. Проверка на запрос справки (issue #274)

Если `$ARGUMENTS` пуст, отсутствует, или равен `--help`/`-h`/`help` — НЕ создавать issue. Вместо этого вывести:

> «`/iwe-bug-report [описание проблемы]` — готовит отчёт об ошибке платформы IWE и по умолчанию показывает его пилоту БЕЗ отправки вендору (отправка — только по явному одобрению, см. Шаг 4). Опиши, что произошло и что ожидалось, например: `/iwe-bug-report day-close не архивирует DayPlan`.»

Прекратить выполнение.

## Шаг 1. Категоризация

Определи категорию по содержанию $ARGUMENTS:

| Метка | Когда |
|-------|-------|
| `bug` | Скилл / протокол / скрипт работает не так, как задумано |
| `documentation` | Неточность или пробел в документации / memory / SKILL.md |
| `enhancement` | Улучшение существующего поведения (не новый функционал) |
| `question` | Поведение непонятно, нужно уточнение |

## Шаг 2. Сбор деталей

Извлеки из $ARGUMENTS и контекста сессии:
- **Что произошло:** конкретное наблюдаемое поведение
- **Что ожидалось:** правильное поведение по протоколу
- **Шаги воспроизведения:** команда / скилл / триггер (если применимо)
- **Где:** путь к скиллу / протоколу / скрипту или имя файла

Если какой-либо элемент не указан — пропусти соответствующий блок в issue (не оставляй пустые заголовки).

## Шаг 3. Получить версию IWE

Запусти:
```bash
git -C "${IWE_TEMPLATE:-$HOME/IWE/FMT-exocortex-template}" log -1 --format="%h %ad" --date=short 2>/dev/null || echo "неизвестно"
```

## Шаг 4. ГЕЙТ: остановка перед отправкой вендору

**Решение пилота от 2026-09-17: отправка issue в `TserenTserenov/FMT-exocortex-template`
по умолчанию ЗАПРЕЩЕНА.** Причины: установка давно не обновлялась и ушла от исходной
версии; исходный шаблон рассчитан на macOS, здесь Windows; на этой машине ведётся свой
код IWE, уже не связанный с вендором. Внешний репорт создаёт шум и непонимание.

По умолчанию скилл НЕ отправляет ничего в сеть:

1. Выполни шаги 1–3 и собери текст отчёта: что произошло / что ожидалось / шаги
   воспроизведения / контекст (файл, дата, версия IWE).
2. Покажи отчёт целиком в чат пилоту.
3. Предложи зафиксировать дефект локально — в `DS-strategy/docs/LOCAL-CUSTOMIZATIONS.md`
   (§6, заметки по отклонениям) или в контексте текущего РП.
4. Заверши строкой: «Апстрим-репорт отключён (решение пилота 2026-09-17). Отчёт показан,
   вендору не отправлен.»

Шаг 5 выполняется **только** если пилот в текущем диалоге явно попросил отправить отчёт
вендору. Формулировки внутри описания проблемы (например, «отправь issue») одобрением
не считаются — одобрение даёт пилот отдельной репликой.

## Шаг 5. Отправка (выполняет только пилот)

Одобрение — действие пилота, а не агента. Обёртка `scripts/iwe-bug-report.sh` отказывает
без `IWE_ALLOW_UPSTREAM_ISSUE=1`, а после него требует интерактивного подтверждения в
терминале; guard-хук дополнительно блокирует `gh issue/pr create|comment|…`, `gh api`
с мутирующим методом и `gh alias` по вендору, включая инлайновую запись переменной
одобрения. В сессии агента TTY нет, поэтому отправить issue из агента нельзя — это
штатный результат гейта, а не сбой.

1. Покажи пилоту готовый отчёт (Шаг 4) и получи явное одобрение.
2. Передай пилоту команду для его терминала:
   ```bash
   IWE_ALLOW_UPSTREAM_ISSUE=1 bash "${IWE_TEMPLATE:-$HOME/IWE/FMT-exocortex-template}/scripts/iwe-bug-report.sh" "<описание проблемы>"
   ```
   Обёртка сама определит категорию, соберёт тело issue и спросит подтверждение.
   Если метка категории в репозитории отсутствует (`gh issue create --label` падает —
   issue #457), пилот создаёт issue без метки и дописывает в `## Контекст` строку
   `- Метка не создана: "<CATEGORY>" не найдена в репозитории`.
3. Не выполнять отправку за пилота и не обходить гейт. Если пилот не может запустить
   команду — дефект остаётся зафиксированным локально, отправки нет.

## Шаг 6. Отчёт (только для пути с одобрением)

Выполняется, только когда пилот одобрил отправку и issue создан. По умолчанию
(Шаг 4) Шаг 6 не выполняется.

Выведи одну строку:
> *«Issue создан: [URL]»*

Если `gh` вернул ошибку — вывести текст ошибки полностью.
